# GlaS New-Domain Pilot Protocol

Date: 2026-07-17

## Purpose

MoNuSAC Gate F failed after the one allowed Rescue-F1 action-bank expansion. This protocol pre-registers a GlaS-only diagnostic pilot to test whether the small MoNuSAC oracle gap is dataset-shape specific.

## Allowed Data

- Allowed: GlaS role=train and role=val episodes generated by `scripts/build_episodes.py`.
- Preferred first run: `manifests/episodes/glas/episodes_val.csv`.
- If the strict val split has too few episodes, a separate `trainval` exploratory diagnostic may be run and labeled as non-formal.
- Prohibited: GlaS `episodes_test.csv`, official testA/testB masks, MoNuSAC test behavior, IDRID test behavior.

## Frozen Components

- Matcher: DINOv2-L checkpoint recorded in `reports/matcher_runtime.json`.
- Segmenter: SAM-B checkpoint recorded in `reports/matcher_runtime.json`.
- Candidate generator: current Gate C candidate kernel, no GlaS-specific tuning.
- Action bank: frozen `configs/actions/prompt_set_bank_v2.json`.
- Fusion: frozen `configs/segmenter/fusion_mvp.json`.

## Decision Rules

- If the strict GlaS val pilot has fewer than 10 episodes, it cannot pass formal Gate F by itself.
- If it shows a large action spread, run a separately labeled train/val diagnostic before any formal claim.
- If it is also near-oracle, keep the MoNuSAC pivot as `oracle_analysis_only` and record GlaS as supporting evidence that fixed rules may be sufficient for this bank.
- No GlaS result may re-open MoNuSAC post-hoc action redesign.
