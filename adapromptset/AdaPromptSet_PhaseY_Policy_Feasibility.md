上尝试大量动作后取最大 Dice。动作越多，最大值越可能被以下因素抬高：- reference sampling noise；- query-specific 偶然波动；- mask threshold sensitivity；- action selection noise；- 数值波动。这称为：```textWinner's CurseMaximum Selection BiasOracle Optimism```本轮必须验证：> A_large oracle gap 0.0708 在新的 query、独立 reference sets 和交叉评估中是否仍然存在。## 1.2 质疑二：10 个 episodes 是否足以支持动作异质性Phase X 的所有核心结论只来自 10 个 validation episodes。10 个单位足以发现旧动作库漏洞，但不足以证明：- 最优 K+ 分布稳定；- 最优 K- 分布稳定；- grouping preference 稳定；- Oracle gap 有可靠置信区间；- 动作差异可在新 query 上泛化；- policy 可以训练。本轮必须扩大独立 query 数量，并以 query/case 为统计单位。## 1.3 质疑三：Search Oracle 是否只是不可学习的逐图过拟合Search Oracle 使用 GT 和平均约 558 次 SAM 搜索调用，为每个 query 找到具体点子集。它做的不只是选择：```textK+K-groupingcalls```还选择了：```text具体哪些 positive candidates具体哪些 negative candidates哪些点被 add/remove/swap```因此：```textSearch Oracle 0.7256```不是 91-action router 的直接上限。本轮必须分开验证：1. **Bank-Action Policy**：只选有限动作配置；2. **Point-Subset Policy**：真正学习具体点子集。## 1.4 质疑四：Search Oracle 的“matched budget”只能解释部署接口，不代表公平自动方法Search Oracle 最终 prompt 只需 1 次 SAM 调用，但找到该 prompt 需要：- query GT；- 数百次 SAM search calls。因此它只能证明：> 单次 SAM 调用的 prompt interface Gate Y1：Fresh-Query Action Heterogeneity本 Gate 先不训练 policy。目标：> 检查 Phase X 中的动作异质性是否在新的 query 上复现。在 Policy Validation Queries 上，分别使用 Reference Set A 和 B 计算完整 utility matrix。## 8.1 必须计算的四种上限### Fixed-A在 Reference Set A 上选出的 strongest fixed：\[a^*_{fixed,A}=\arg\max_a\frac{1}{N}\sum_q U_A(q,a)\]### Oracle-A\[U_{oracle,A}=\frac{1}{N}\sum_q \max_a U_A(q,a)\]### Cross-Reference Oracle A→B先在 A 上选每个 query 的 oracle action：\[a^*_{q,A}=\arg\max_a U_A(q,a)\]再在 B 上评价：\[U_{cross,A\rightarrow B}=\frac{1}{N}\sum_q U_B(q,a^*_{q,A})\]### Reverse Cross-Reference Oracle B→A同理计算：\[U_{cross,B\rightarrow A}\]最终稳定 Oracle：\[U_{stable-oracle}=\frac{U_{cross,A\rightarrow B}+U_{cross,B\rightarrow A}}{2}\]## 8.2 Oracle Optimism定义：\[Optimism_A=U_{oracle,A}-U_{cross,A\rightarrow B}\]\[Optimism_B=U_{oracle,B}-U_{cross,B\rightarrow A}\]必须报告：- raw bank oracle；- cross-reference oracle；- stable oracle；- oracle optimism；- strongest fixed；- stable oracle gap。不能只报告 raw oracle。## 8.3 动作稳定性指标必须报告：- exact action agreement；- K+ bin agreement；- K- agreement；- selector agreement；- action rank Spearman correlation；- top-3 action overlap；- utility correlation；- reference-set win consistency。## 8.4 Gate Y1 通过条件必须同时满足：1. Stable oracle gap：\[U_{stable-oracle}-U_{strongest-fixed}\ge 0.015\ Dice\]2. paired bootstrap 95% CI 下界 > 0；3. 至少 30% validation queries 的稳定 best-action family 不同于 strongest fixed；4. cross-reference action-rank correlation：```textmedian Spearman rho > 0.30```5. oracle optimism 不超过 raw oracle gap 的 60%；6. 不是由更多 SAM calls 造成，因为所有动作固定 1 call。通过：```textPHASEY_GATE_Y1_STABLE_HETEROGENEITY```失败分支：```textPHASEY_GATE_Y1_REFERENCE_UNSTABLEPHASEY_GATE_Y1_SELECTION_BIAS_DOMINATESPHASEY_GATE_Y1_ORACLE_GAP_SMALL```Gate Y1 失败后：- 禁止训练 bank-action policy；- 允许转向 point-subset stability audit；- 不允许访问 holdout 或 test 寻找正结果。---# 9. Gate Y2：Search Oracle Stability，而不是只看 Search Dice本 Gate 只用于诊断 Search Oracle 是否稳定。## 9.1 Search 数据边界GT-guided search 只允许运行在：- Policy Train Queries；- Policy Validation Queries。不得运行在：- Confirmatory Holdout；- Formal Test。Confirmatory Holdout 必须只评价自动 policy。## 9.2 双 Reference Search对同一 validation query：1. 用 Reference Set A 运行 search，得到 subset \(S_A\)；2. 用 Reference Set B 运行 search，得到 subset \(S_B\)；3. 交叉评价：   - \(S_A\) 在 B 上的 Dice；   - \(S_B\) 在 A 上的 Dice。必须报告：- raw search Dice；- cross-reference search Dice；- K+ stability；- K- stability；- point-coordinate overlap；- spatial coverage overlap；- candidate-rank overlap；- search optimism；- final prompt area bias。## 9.3 Search Oracle 解释规则### 情况 A：raw 高，cross 也高```textSEARCH_ORACLE_REFERENCE_STABLE```说明搜索找到的 prompt 结构具有稳定性。### 情况 B：raw 高，cross 明显下降```textSEARCH_ORACLE_REFERENCE_OVERFIT```说明 0.7256 主要是 reference/episode 特异搜索结果。### 情况 C：K 不稳定，但 cross Dice 稳定```textMULTIPLE_EQUIVALENT_PROMPTS```说明存在多个性能相近的 prompt 子集，不宜把单一 subset 当唯一标签。### 情况 D：点集和性能均不稳定```textSEARCH_LABELS_NOT_SUITABLE_FOR_SUPERVISION```## 9.4 Gate Y2 判据允许进入 Point-Subset Policy 的最低条件：1. cross-reference search 相对 strongest fixed：\[\ge 0.03\ Dice\]2. paired bootstrap CI 下界 > 0；3. search optimism <= raw search gap 的 50%；4. 最终 K+ 的跨 reference 中位绝对差：```textmedian |K_A-K_B| <= 8```或者虽 K 不一致，但 cross Dice 差异 <=0.01；5. 至少 70% query 上，A-search prompt 在 B 中仍胜过 strongest fixed。通过：```textPHASEY_GATE_Y2_SEARCH_LABELS_STABLE```否则：```textPHASEY_GATE_Y2_SEARCH_ORACLE_OVERFIT```---# 10. Track B：Point-Subset Policy只有以下任一条件满足才允许进入：1. Gate Y2 通过；2. Gate Y1 通过但 Bank Policy 无法追回足够 Oracle；3. Bank Policy 通过后，作为增量方法研究。## 12.1 Point-Subset 任务定义给定最多 100 个 positive candidates：\[C^+=\{c_1,\dots,c_M\}\]学习每个候选的 marginal utility：\[u_i=f(c_i,z_q)\]或者条件边际增益：\[\Delta u_i=f(c_i,S_{selected},z_q)\]然后在 one-call one-group 下选择具体 subset。## 12.2 Search 标签只能来自 Train QueriesGT-guided search trajectory 只能在 Policy Train Queries 生成。保存：- add/remove/swap trajectory；- selected subset；- marginal Dice gain；- rejected points；- K stopping point；- negative selection；- search cost。Validation 与 Holdout 不得用 search label 训练。## 12.3 模型阶梯### P0. Top-K contrast固定 K=20/25。### P1. Pointwise marginal regression预测每点独立 utility。### P2. Pairwise point ranking学习点 i 是否优于点 j。### P3. Diversity-aware reranker综合：- predicted utility；- 与已选点距离；- feature redundancy；- local density。### P4. Set encoder使用 DeepSets 或轻量 Set Transformer。### P5. Learned greedy marginal selector逐步选择点并预测 stop。禁止：- 用 validation GT 做 point swap；- test-time SAM search；- inference 时尝试几十个 subsets；- PPO/DQN。## 12.4 Point-Subset Baselines必须比较：- Top20 contrast；- Top20 spread；- Top20 local peaks；- fixed Top20 + N1；- Bank-Action Policy；- random 20-point subset；- GT-guided Search Oracle，上界；- cross-reference Search Oracle，上界。## 12.5 Gate Y4：Point-Subset LearnabilityValidation 通过条件：1. 比 strongest fixed 提升：\[\ge 0.015\ Dice\]或者比 Bank Policy 提升：\[\ge 0.0075\ Dice\]2. paired bootstrap CI 下界 > 0；3. 同一最终 prompt 只调用 1 次 SAM；4. inference 不进行 SAM search；5. 3 seeds 方向一致；6. 至少追回 cross-reference Search Oracle gap 的 20%；7. reference-set A/B 下方向稳定；8. K 分布不退化为所有 query 相同。通过：```textPHASEY_GATE_Y4_POINT_SUBSET_PASS```失败：```textPHASEY_GATE_Y4_SEARCH_ORACLE_NOT_LEARNABLE```---# 13. 搜索 Oracle 和自动方法的表格口径所有主表必须分成三块。## 13.1 Automatic Deployable Methods包括：- fixed dense；- heuristic；- bank policy；- point-subset policy。报告：- Dice；- IoU；- AJI；- component recall；- calls；- runtime；- model parameters。## 13.2 Finite-Bank Upper Bounds包括：- raw bank oracle；- stable cross-reference oracle。必须标：```textuses query GT for action identificationnot deployable```## 13.3 Search Upper Bounds包括：- raw search oracle；- cross-reference search oracle。必须同时报告：- final deployed calls；- search calls；- GT access；- optimism。禁止把 Search Oracle 放在 automatic method 中间，而不注明 privileged search。---# 14. 统计协议## 14.1 独立单位```textquery/case```不是：- reference episode；- candidate point；- prompt action；- patch；- SAM call。## 14.2 主要比较预注册 Primary Comparison 1：```textBank Policy vs Strongest Fixed Dense```Primary Comparison 2，仅 Track B 合法时：```textPoint-Subset Policy vs Bank Policy```其他为 secondary。## 14.3 统计输出必须报告：- mean；- median；- paired difference；- paired bootstrap 95% CI；- win/tie/loss；- effect size；- seed mean/std；- reference sensitivity；- catastrophic failure；- oracle recovery。## 14.4 多重比较使用 Holm correction 处理多个 learned models 对 strongest fixed 的比较。不得只报告显著模型。---# 15. 必须生成的表格1.
